# Worldgen source

Ported from Alex's [Paper-Minecraft PR #1](https://github.com/CowgillAlex/Paper-Minecraft/pull/1), commit `d681c0532d5e2628c70e6de7fad7df31f64ea705`.

`overworld.json` packages the original Overworld height/sea-level settings and eleven density-router roots: final density, initial density without jaggedness, barrier, fluid-level floodedness and fluid-level spread, plus temperature, vegetation, continents, erosion, depth and ridges. Referenced density and noise definitions are copied from `assets/data/minecraft/worldgen`. Names retain their original paths, with the `minecraft:` namespace retained inside references. Unused router roots and feature data are excluded. Surface rules are bundled separately.

The Rust port follows `VanillaNoiseStep.java`, `VanillaAquifer.java`, `Xoroshiro.java`, `ImprovedNoise.java`, `PerlinNoise.java` and `NormalNoise.java`. ImprovedNoise uses the exact gradient table from `SimplexNoise.java`. This preserves the project's own RNG and noise behavior, including details which may differ from other Minecraft implementations.

The intended changes for MiniCraft are fractional metre coordinates and 3D interpolation. Java's integer X/Y density adapter becomes a double-coordinate adapter; its bilinear 4 × 8 cell interpolation becomes trilinear 4 × 8 × 4 interpolation. No new noise or terrain-detail layer is added. At Z=0 the original interpolation arithmetic is preserved. The aquifer now restores all three spatial axes: 16 × 12 × 16 metre fluid cells, 12 candidate cells per sample, XYZ seed names and distance checks, all 13 X/Z surface-neighborhood samples, 3D floodedness/level spread and 3D barrier noise. Preliminary surfaces use a 4 metre X/Z lattice and scan the initial density in 8 metre vertical steps with the 0.390625 threshold. The [Deepslate aquifer implementation](https://github.com/misode/deepslate/blob/54b191dd5557381e0ed7851f17b7b19c28fbe871/src/worldgen/Aquifer.ts) and [preliminary surface scan](https://github.com/misode/deepslate/blob/54b191dd5557381e0ed7851f17b7b19c28fbe871/src/worldgen/NoiseChunk.ts#L61) were consulted for the 3D layout and surface lattice. Paper-Minecraft's existing flooding and pressure math remains the basis; this is not a claim of identical vanilla Minecraft seeds. Java's unimplemented lava band remains air. Noise/material evaluation covers the original vertical range of -64 to 320 metres.

`java-slice.json` contains output from the unmodified Java noise and aquifer classes. `java-continuous.json` uses the same Java code with only the coordinate type and interpolation adapter changed. Both include named RNG outputs for the same six seeds. These two historical fixtures now check density only, allowing `1e-12` floating-point error; their old 2D material IDs are intentionally no longer expected. `java-aquifer3d.json` contains 3,564 material outputs from the same Java code extended to XYZ aquifers by `scripts/aquifer_reference.py`. Those material IDs must match exactly in either sampling order. The Java oracle uses its map-based candidate lookup, independently of the Rust per-neighborhood cache. These are reference outputs, not Rust-generated snapshots.

`scripts/worldgen-reference.py` fetches source content from the pinned commit in an existing local reference checkout and compiles it in a temporary directory. Small LibGDX/registry stubs supply file reads, configuration loading and material IDs without starting the old game. Its unused JsonValue entry points throw if called. The script needs a JDK and Gson but the game and ordinary Rust tests do not. Run it from any directory with the reference repository path as its argument.

## Exact generation optimizations

Workers retain bounded interpolation-cell and corner caches across pages. Interval bounds propagate through the density graph. An interpolated field uses its corner extrema only when a page lies inside one interpolation cell; unsupported bounds fall back to fine sampling. Uniform fluid decisions require all possible contributing aquifer statuses to agree, preserving pressure barriers. A graph-validated prepared evaluator reads the bundled expression constants and evaluates the same five trilinear fields per voxel. Different graph shapes fall back to the generic evaluator. Near-zero final densities also use the generic path.

Uniform 32³-voxel pages store one material byte; mixed pages retain all fine material cells. These optimizations do not change the metre scale or replace fine geometry with coarse samples. Tests compare optimized pages byte-for-byte with reference fills and compare prepared density against the independent Java fixture. `--reference-worldgen` retains the original per-voxel fill for diagnostic comparisons.

Signed horizontal page coordinates extend the same source field beyond the original finite window. Infinite streaming does not change density or aquifer decisions. Sky lighting scans source columns above resident pages, using conservative interval skips and fine fallback so unloaded roofs still occlude the sky. Interpolation, aquifer and sky caches are bounded; evicting cached samples only causes deterministic recomputation.

The streaming path caches conservative whole interpolation-cell classifications, and subdivides mixed pages into 16³ and 8³ voxel boxes before their fine fallback. Sky rays group vertical work by the same 8 metre interpolation boundaries. A cached prepared expression accelerates exact point samples used by lighting transport. All shortcuts retain the near-zero generic fallback and Java material fixtures.

## Surface port

`surface.json` contains the pinned Overworld `surface_rule` and its eleven named noise definitions. `biomes.json` exports all 7,594 ordered parameter entries directly from the pinned `BiomeManager.java` using reflection. The source's four depth-band column candidates and first-entry tie order are preserved. Biome cells are four metres across, sampled at their centres; the five horizontal channels use Y=63 and depth uses each cell's Y. X/Z are restored as spatial axes. No new climate noise is introduced.

Rules follow `SurfaceRules.java`, `SurfaceSystem.java` and `VanillaSurfaceRuleEngine.java`, including rule order, floor/ceiling stone depths, water context, preliminary height, steepness, positional gradients and clay bands. Preliminary heights retain the original one-metre Y lattice. Fine-column runs and water heights use the unmodified raw material field across streaming pages; their distances stay in metres. The source's `is_3d` noise flag is ignored by its JSON parser, so this port also evaluates those condition noises horizontally. This preserves pinned behavior rather than silently changing the sulfur cave rule. The 3D extension adds Z to horizontal noises, steepness checks, clay offsets and positional hashes; at Z=0 it retains source arithmetic. Gradients use source integer-metre positional coordinates and internal Y=world Y+64. Terracotta uses the exact java.util.Random stream, while other generation retains the source xoroshiro stream.

`scripts/surface-assets.py` reproduces the assets from the pinned Git objects. `scripts/surface-reference.py` compiles the actual Java rule engine against synthetic raw columns and exports 1,575 columns (66,150 material samples), 15 band sequences and 3,584 biome selections into `java-surface.json`. Its stubs supply raw geometry/known height profiles and block names, while the original Java rules, surface noise and random implementation produce the expected values. Generated Rust pages also check generation order, point queries, and optical parity. Ordinary builds embed the data and require neither Java nor the reference repository.

Decoration runs only after raw page generation and before lighting/meshing. It replaces source stone only. Cached uniform optical proofs are discarded in biomes where rules may emit air or water; unknown light queries evaluate those rules before answering. Opaque material replacements share stone's transport response. The default `Preview` used by raw diagnostic tests keeps decoration disabled; the application's argument parser enables it unless `--noise-only` is present.
